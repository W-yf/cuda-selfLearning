## RV-D1-001：返回流程的时间顺序

**问题**

不考虑异常，函数按值返回且没有 NRVO 时，请按先后顺序说明：计算 `return` 表达式、初始化返回结果对象、销毁函数局部对象、函数结束、调用方使用结果、结果对象最终销毁。

**答案要点（回答后核对）**

1. 计算 `return` 表达式；
2. 初始化函数调用的结果对象；
3. 销毁 `return` 表达式相关的临时对象，然后按规则销毁函数局部对象；
4. 被调用函数结束，控制权回到调用方；
5. 调用方继续使用结果；
6. 结果对象在调用方决定的生命周期终点销毁。它不是函数退出时销毁的普通局部对象。

**常见错误**

- 认为返回结果对象会在函数结束前被销毁；
- 把“结果已经初始化”误说成“调用方已经继续执行”；
- 忽略 NRVO 时局部对象与结果对象可能是同一个对象。

## RV-D1-002：C++17 保证复制消除与 NRVO

**问题**

比较下面两种返回形式。在 C++17 中，哪一种保证不需要从返回表达式复制/移动，哪一种仍依赖可选 NRVO？若 NRVO 发生，默认构造函数是否还会执行？

```cpp
Person make_prvalue()
{
    return Person{};
}

Person make_named()
{
    Person local;
    return local;
}
```

**答案要点（回答后核对）**

- `return Person{};` 属于 C++17 保证的直接构造情形，不先创建一个独立临时对象再移动。
- `return local;` 是 NRVO 候选，C++17 仍不强制编译器实施 NRVO。
- NRVO 发生时，`local` 直接构造在结果对象的存储位置；默认构造仍执行一次，只消除了复制/移动。
- NRVO 未发生且移动可用时，从 `local` 移动构造结果对象。

## RV-D1-003：按值返回与悬空观察者

**问题**

为什么返回局部 `std::string` 的值通常安全，而返回该局部对象的引用或地址不安全？回答时指出谁拥有独立对象、谁只是观察者，以及局部对象何时结束生命周期。

**答案要点（回答后核对）**

- 按值返回会初始化一个在调用表达式中继续存活的结果对象，可能复制、移动或直接构造。
- 引用和裸指针通常只是非拥有观察者，不会延长局部对象生命周期。
- 普通局部对象在函数退出过程结束生命周期；继续通过引用或地址访问会悬空并产生未定义行为。

## RV-D1-004：C++11/14 未消除时的移动次数

**问题**

假设 `Person` 可移动、不是 `const`，并且在 C++11/14 中完全不进行复制消除：

```cpp
Person create()
{
    Person a;
    return a;
}

Person b{create()};
```

分别会调用多少次默认构造、移动构造和拷贝构造？C++17 中为什么至多只剩一次移动？

**答案要点（回答后核对）**

- C++11/14 完全不消除：默认构造一次，移动构造两次，拷贝构造零次。
- 第一次从 `a` 构造函数结果，第二次从结果临时对象构造 `b`。
- C++17 中，函数调用产生的纯右值直接初始化 `b`，不再有“结果临时对象再移动到 `b`”这一步；`return a;` 未 NRVO 时仍可能有从 `a` 到结果的一次移动。

## RV-D1-005：六个特殊成员函数

**问题**

请列出 C++ 类的六类特殊成员函数，并用一小段代码区分“拷贝构造”和“拷贝赋值”。为什么不能说每个类一定自动获得六个可用实现？

**答案要点（回答后核对）**

- 默认构造、析构、拷贝构造、拷贝赋值、移动构造、移动赋值。
- `Person b{a};` 是用已有 `a` 创建新对象 `b`，属于拷贝构造；先创建 `b` 再执行 `b = a;` 属于拷贝赋值。
- 用户声明某些构造或析构/复制/移动操作会影响其他特殊成员的隐式声明；成员不可复制或不可移动时，相应函数还可能被定义为删除。

## RV-D1-006：Lambda 引用捕获的生命周期

**问题**

下面代码为什么不安全？只修改捕获方式并保持 `std::function<std::string()>` 的无参数调用签名，应如何修复？

```cpp
std::function<std::string()> make_reader()
{
    std::string text{"sample"};
    return [&text] { return text; };
}
```

**答案要点（回答后核对）**

- 返回的闭包对象可以继续存在，但局部 `text` 在函数退出时结束生命周期。
- `[&text]` 只保存非拥有引用关系，随后悬空。
- 改为 `[text] { return text; }`，闭包对象在 Lambda 表达式求值时保存独立副本。
